# AGENTS.md

Instructions for AI coding agents working in the AK Pharma Management System.

## Project understanding

AK Pharma is an internal pharmaceutical ERP: inventory and FEFO stock, doctors and field force, pharmacy sales, procurement, treasury, payroll, RBAC, and an audit trail. The UI is a Next.js app. The API is Express. Data is stored in MongoDB through Prisma.

Stack:

- Frontend: Next.js 16 App Router, React 19, TypeScript, Tailwind CSS v4, shadcn/ui, Sonner, Zod
- Backend: Express, TypeScript, Prisma, MongoDB, Zod, JWT, bcrypt

Read the detailed docs before changing the matching layer:

- [docs/SYSTEM_OVERVIEW.md](docs/SYSTEM_OVERVIEW.md) — how the system fits together
- [docs/FRONTEND_GUIDELINES.md](docs/FRONTEND_GUIDELINES.md) — frontend structure, data loading, forms, and validation
- [docs/BACKEND_ARCHITECTURE.md](docs/BACKEND_ARCHITECTURE.md) — request lifecycle, layers, and API contracts
- [docs/UI_UX_GUIDELINES.md](docs/UI_UX_GUIDELINES.md) — visual system and interaction patterns

`frontend/AGENTS.md` is generated by Next.js. Do not treat it as the product guide and do not delete it.

## Mandatory rules before coding

1. Read `docs/SYSTEM_OVERVIEW.md` before making architectural changes.
2. Read `docs/FRONTEND_GUIDELINES.md` before modifying frontend code.
3. Read `docs/BACKEND_ARCHITECTURE.md` before modifying backend code.
4. Read `docs/UI_UX_GUIDELINES.md` before creating or modifying UI components.
5. Inspect the relevant source files before implementing changes.
6. Follow existing project conventions instead of introducing unnecessary new patterns.
7. Never duplicate existing functionality without checking whether reusable code already exists.
8. Do not introduce new dependencies without a valid reason.
9. Do not expose secrets or environment variable values.
10. Avoid unrelated changes and unnecessary refactoring.

Established conventions that are easy to miss:

- Backend flow is route → Zod → controller → service → Prisma. Controllers use `catchAsync` and `sendResponse`. Controllers do not import Prisma and do not use `try/catch`.
- The database is MongoDB. Older notes that say PostgreSQL are wrong.
- Frontend mutations use Sonner (`toast.loading`, `toast.success`, `toast.error`). Do not use `alert()`.
- Deletes use `DeleteConfirmationModal` from `@/components/ui/delete-confirmation-modal`. Do not use `window.confirm()`.
- New screens that belong in the permission matrix must be added to `backend/src/constants/moduleCatalog.ts` and `frontend/lib/permissions.ts` together.
- `SystemRole` is login security. `Role` is an HR job title. Do not merge them.
- Most existing API routes do not call `requireAuth`. That is a gap, not a pattern to copy. New sensitive routes should authenticate and authorize.

## Validation rules

- Follow the existing frontend and backend validation strategies.
- Never rely exclusively on frontend validation for security.
- Validate incoming data on the backend.
- Keep validation schemas consistent with actual API contracts.

Frontend forms that already have schemas use Zod `safeParse` and map issues onto field errors. Backend routes use `validateBody`, `validateParams`, and `validateQuery` in `backend/src/utils/validate.ts`. When a module has both `frontend/lib/validations/<module>Validation.ts` and `backend/src/validations/<module>Validation.ts`, update both. Login passwords are required. Provisioned user passwords are at least 6 characters. Email checks use Zod `.email()` where those schemas already do. Phone numbers are required strings, not a phone-number pattern.

- Update `docs/SYSTEM_OVERVIEW.md` if system behavior changes.
