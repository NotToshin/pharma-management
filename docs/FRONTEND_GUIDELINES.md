# Frontend Guidelines

Next.js App Router app in `frontend/`. Pages are client components. They call Express with `apiFetch` and keep form state in `useState`. Visual rules are in [UI_UX_GUIDELINES.md](./UI_UX_GUIDELINES.md). Request contracts are in [BACKEND_ARCHITECTURE.md](./BACKEND_ARCHITECTURE.md). Sessions are in [AUTHENTICATION.md](./AUTHENTICATION.md).

## Stack and layout

Next.js 16.3, React 19, TypeScript `strict`, Tailwind CSS v4 (no `tailwind.config`), shadcn `radix-nova`, Lucide, Sonner, Recharts, `xlsx`, `date-fns`, `react-day-picker`, `next-themes` (shell forces light). Not used: Redux, Zustand, React Query, SWR, React Hook Form, Formik, Yup.

Zod is imported by `frontend/lib/validations/*` but is not a direct `frontend/package.json` dependency. It arrives through the lockfile. If a clean install cannot resolve it, add it there. Do not replace the schemas.

`@/*` maps to `frontend/*`. Scripts: `dev`, `build`, `start`, `lint`, `typecheck`, `format`. `next.config.ts` sets `typescript.ignoreBuildErrors: true`. Use `npm run typecheck` when types must fail the build. `frontend/AGENTS.md` is generated by Next.js. Do not edit it.

```text
frontend/
├── app/layout.tsx          # shell, sidebar, auth gate, toasts
├── app/page.tsx            # redirects to /dashboard or /login
├── app/<area>/<screen>/page.tsx
├── components/app-sidebar.tsx
├── components/permission-gate.tsx
├── components/server-list-controls.tsx
├── components/ui/          # shadcn primitives
├── components/finance|logistics|procurement/
├── hooks/use-mobile.ts
├── hooks/usePermission.ts
├── lib/api.ts
├── lib/auth.ts
├── lib/permissions.ts
├── lib/validations/        # doctor, client, visit log
└── middleware.ts
```

Routes are files. There is no `pages/` router. Shared UI stays in `components/ui/`. Extract a feature component only when a second page needs it (`purchase-order-sheet.tsx`, `invoice-details-form.tsx`, `party-settlement-page.tsx`).

| Kind | Pattern |
|---|---|
| Page | `app/<area>/<screen>/page.tsx` |
| Feature component | kebab-case file, PascalCase export |
| Validation | `lib/validations/<entity>Validation.ts` exporting `<entity>FormSchema` |
| Permission feature | Exact `moduleCatalog` label, for example `"Pharmacy Clients"` |

## Routing

`frontend/middleware.ts` ignores `api`, static files, and `favicon.ico`. It cannot read `localStorage`.

- `/` → `/dashboard` or `/login`
- `/login` with a session → `/dashboard`
- any other path without a session → `/login?from=<path>`
- `/settings/rbac` without super-admin role text or `ak_rbac=true` → `/dashboard?unauthorized=rbac`

Add a page to `routeTitleMap` in `app/layout.tsx` (title `AK-Pharma | <page>`), `navSections` in `app-sidebar.tsx`, `ROUTE_FEATURES` in `lib/permissions.ts`, and `ALL_SYSTEM_MODULES` together. `/doctors/timeline` and `/field-force/approvals` are pages outside the sidebar and `ROUTE_FEATURES`.

The sidebar hides items the user cannot `view`. The Pharmacy Clients badge is replaced by the `/api/clients` count.

## State and API

Page state is `useState`. There is no server-data cache. After a mutation, call that page's `fetchData()`. Session keys and refresh behavior are in [AUTHENTICATION.md](./AUTHENTICATION.md). `usePermission` reads the stored user and the `ak-permissions-updated` window event.

Authenticated calls use `apiFetch` from `frontend/lib/api.ts`. Login uses plain `fetch`.

```typescript
const res = await apiFetch(getEndpoint("/doctors"), {
  method: "POST",
  body: JSON.stringify(parsed.data),
})
```

`getEndpoint` accepts `/doctors`, `doctors`, or `/api/doctors` and returns one `/api` base. Do not hard-code `localhost`. Success payload is `json.data`. Lists also return `json.meta`. Old callers sometimes get a raw array: `json.data ?? json`. Read `message` from error JSON. There is no frontend `services/` API layer.

| Result | UI |
|---|---|
| Zod `safeParse` failure | Field map plus `toast.error` |
| HTTP error | `toast.error` with `message` |
| Network throw | “Network error…” toast |
| 401 after refresh fails | `apiFetch` redirects to `/login?expired=1` |
| Page not permitted | Rose access-denied panel in the layout |
| Saving | `toast.loading`, then success or error with the same id |
| Delete | `DeleteConfirmationModal`. Never `window.confirm` or `alert` |

Shell boot shows “Loading...” until mounted, then “Authenticating secure session...” until the session check finishes.

## Validation

Forms are controlled inputs. Client Zod does not secure the API. When both copies exist, keep `frontend/lib/validations/` and `backend/src/validations/` aligned.

| Schema | Used by |
|---|---|
| `doctorFormSchema` | `app/doctors/database/page.tsx` |
| `clientFormSchema` | `app/sales/clients/page.tsx` |
| `visitLogFormSchema` | `app/field-force/visit-logs/page.tsx` |

Other screens use local `if` checks and `toast.error`. RBAC provisioning requires name, email, and password length ≥ 6. Login only checks non-empty fields, then the API.

Encoded rules:

- Doctors: `doctorName`, `phone`, `bmdcRegNumber`, `specialtyAndInstitute`, `chamber`, `tier` required. `email` required and `.email()`. `patientVolumeDaily` coerced integer ≥ 0. `territoryAndMio` defaults to `"Unassigned"`.
- Clients: `pharmacyName`, `phone`, `territory` required. Credit amounts coerced and ≥ 0. `creditTermDays` integer ≥ 0, default 30. `status` enum `Active / Healthy`, `Credit Hold`, `Watchlist`, `Cash Only`.
- Login API: email format, password `min(1)`.
- User provisioning API: email format, password `min(6)`, name and `roleCode` required.
- Phones are required strings. There is no phone regex and no password rule beyond length 6. Money inputs need `z.coerce.number()`.

New form, matching `handleAddDoctor` in `app/doctors/database/page.tsx`:

1. `safeParse` the payload. Map `issue.path[0]` into `formErrors`. Toast a short summary and return.
2. `toast.loading`, then `apiFetch` `JSON.stringify(parsed.data)` so coerced numbers are sent.
3. On `res.ok`, `toast.success` with the same id, close the dialog, reload.
4. On failure, toast `errorData.message`. Server `errors: [{ field, message }]` are not written back onto inputs.
5. Updates on the doctors page use `schema.partial().safeParse`.

## Permissions in the UI

1. Middleware checks a session cookie. Only `/settings/rbac` has a role check there.
2. The layout calls `featureForPath` and `userCan(user, feature, "view")`. Unknown paths stay visible.
3. `PermissionGate` and `usePermission().can(feature, action)` hide buttons. Actions: `view`, `create`, `edit`, `delete`, `special`. `view` is the `read` field. Cards use `overview:<key>`.

```tsx
<PermissionGate feature="Doctors List" action="create">
  <Button>Add doctor</Button>
</PermissionGate>
```

`feature` must be the catalog string. Super admins pass. An empty `permissions` array also passes. Once rows exist, a missing module is denied.

## Lists, files, and new code

New paging goes through `frontend/components/server-list-controls.tsx`: `useServerListQuery`, `ServerListToolbar`, `ServerListPagination`. The query string sends `page`, `limit`, `sortOrder`, plus `search` and `searchTerm` when the user typed, `sortBy` when set, and filters whose value is not `all`. Search, sort, filter, and page size reset to page 1. Render `meta.total` and `meta.totalPage` or `meta.totalPages`. Audit Logs and the RBAC operator table already do this. Older screens still filter in memory. Extend the backend query schema before replacing that. Do not add a second pager. `components/ui/pagination.tsx` is the primitive the shared control uses.

Excel: read `.xlsx` / `.xls` with `XLSX.read`, map rows, `POST` JSON to `/bulk-import`. Doctors and clients do this. Empty sheets toast and do not call the API. Avatars are `FileReader` data URLs stored on the local user, not uploaded.

Use primitives in `components/ui`. Import `cn` from `@/lib/utils`. Do not add a form or data-fetching library for one screen. The root layout is a client component, so the document title is set in an effect, not `metadata`.
